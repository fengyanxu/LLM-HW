# P137：Gensim 表示学习与 FastText 新闻分类实验报告

## 1. 实验目标与主要结果

本实验完成了语料清洗、表示学习、文档向量构建、逐级分类、参数选择、源码核对和图表生成。分类标签采用人民日报原始文章编号中的版面字段，依次开展第 01—02 版、第 01—04 版和第 01—06 版分类。标签表示实际版面位置，版面主题与文章主题的联系由数据体现。

作业的高级要求落实为三组工作：使用 Gensim 训练多种表示并完成分类，围绕论文与实现解释训练目标，进一步检查词表、任务调度、采样、内存、序列化和参数设置。

### 2.1 Gensim 框架论文的关键认识

2010 年论文将语料定义为“可以逐篇返回文档的可迭代对象”，每篇文档使用 `(词项编号, 数值)` 列表表示。模型则承担向量空间转换，通过 `model[document]` 或 `model[corpus]` 使用。这个设计使同一份文档能够依次进入词频、TF-IDF 和 LSI 空间，转换过程可以按需计算。

论文讨论了流式 LSA 的增量 SVD，并在数学文献数字图书馆中比较多种表示。它强调，流式处理让训练语料规模与整份语料的内存驻留需求分离；模型内存仍由词表、潜在维度及中间计算决定。本实验的逐句迭代器遵循同样的思路，词向量矩阵与子词桶占用则由专门的资源实验观察。

2010 年论文对应早期框架设计。当前 Gensim 4.3.0 的 LSI 使用分块计算、随机 SVD 与投影合并等具体实现，源码版本及算法路径需要逐项核对。下文将框架设计原则与当前函数对应，并将 FastText 子词训练作为独立算法展开。

## 5. 从论文到词向量：深入浅出的解释

### 5.1 Word2Vec 的上下文预测

Skip-gram 根据中心词预测附近的词，CBOW 根据附近的词预测中心词。例如，“经济 市场 银行”提供了这些词共同出现的训练信号。大量上下文会逐渐调整向量，使相关词具有相近的表示。

负采样将每个真实词对与随机词对进行比较。一个正样本对应的损失可写为：

$$
\mathcal{L}=-\log\sigma(\mathbf{u}_w^{\mathsf{T}}\mathbf{v}_c)
-\sum_{i=1}^K\log\sigma(-\mathbf{u}_w^{\mathsf{T}}\mathbf{v}_{n_i}).
$$

中心词与真实上下文的得分需要提高，与采样词的得分需要降低。输入向量和输出向量分别承担表示中心对象与上下文对象的作用。

### 5.2 FastText 的子词共享

子词论文把一个词表示为字符 n-gram 的集合，并加入边界符号。例如 `where` 的长度为 3 的子词包括 `<wh`、`whe`、`her`、`ere`、`re>`，完整词本身也具有专门的表示。词语共享字符片段，使低频词可以利用其他词中已经学到的子词信息。[1]

论文中的得分为：

$$
s(w,c)=\left(\sum_{g\in G_w}\mathbf{z}_g\right)^{\mathsf{T}}\mathbf{v}_c.
$$

Gensim 保存完整词与子词的两组输入矩阵，训练核心依据组合表示预测上下文。它在组合和导出阶段包含具体的归一化处理；`adjust_vectors()` 导出的已见词向量为完整词向量与哈希子词向量的均值：

$$
\mathbf{e}_w=
\frac{\mathbf{z}_w+\sum_{g\in G_w}\mathbf{z}_{h(g)}}{1+|G_w|}.
$$

词表外输入通过字符片段组合生成向量。能够生成向量说明计算覆盖能力，向量表达质量仍然需要近邻分析与下游实验支持。哈希碰撞还会使不同片段共享参数，因此需要检查容量与效果之间的关系。

### 5.3 论文参数与 Gensim 默认值

主论文采用 300 维、5 个负样本、3—6 字符子词和 2,000,000 个哈希桶。其负采样概率按词频平方根设置，降采样阈值为 0.0001，子词模型起始学习率为 0.05；Gensim 4.3.0 默认 `ns_exponent=0.75`、`sample=0.001`、`alpha=0.025`。这些差异直接体现在源码参数和采样表中。[1][2]

本实验根据中文分词新闻的规模与 CPU 资源选择 64 维、2—4 字符子词及 50,000 个桶作为基准，并分别测试论文采用的采样指数、学习率和降采样阈值。原论文的语料、语言与评价任务各有条件，中文版面分类通过本地验证确定参数。

### 6.1 词表和采样控制学习信号

`min_count` 决定词语能否获得独立的词向量。`sample` 控制高频词的保留概率，使训练更集中于有辨别力的上下文。`ns_exponent` 通过下面的概率影响负样本来源：

$$
P_{\mathrm{neg}}(w)=\frac{f(w)^{\eta}}{\sum_{v\in V}f(v)^{\eta}}.
$$

指数为 1 时按词频采样，为 0 时趋向均匀采样；0.5 和 0.75 在二者之间形成不同分布。`make_cum_table` 预先保存累计概率，训练核通过随机数和查表选择负样本。这些周边步骤决定训练目标接收到的实际数据。

### 6.2 Python 调度与 Cython 更新

Python 层承担输入检查、词表、任务队列、回调和保存；Cython 层承担主要的点积与向量加法，并调用 BLAS 操作。`_job_producer` 将文本打包为任务，`_worker_loop` 消费任务，`_do_train_job` 进入训练核。FastText 继承 Word2Vec 的通用训练框架，并补充子词相关矩阵与组合操作。

这里的 `batch_words` 控制调度粒度。算法仍然围绕上下文样本执行局部更新，队列任务与监督分类器的小批次承担不同功能。`workers` 增加可以利用多核，同时异步参数更新会改变执行顺序。本次选择单词向量训练线程以便复现。

语料迭代器需要在建立词表和每个训练轮次重新读取。项目的 `SentenceCorpus` 每次迭代都打开文件，适合多次扫描；Gensim 的 `_check_corpus_sanity` 也检查输入能否满足多轮训练。

### 6.3 哈希桶、缓存与内存

子词通过稳定的哈希函数映射到固定桶。`recalc_char_ngram_buckets` 为词表词缓存子词索引，训练时可以直接使用这些索引。较大的桶减少共享冲突，也增加矩阵大小。仅子词矩阵的理论存储为：

$$
M_{\mathrm{subword}}=\text{bucket}\times\text{vector\_size}\times 4\ \text{bytes}.
$$

例如，50,000 桶、64 维、float32 的子词矩阵占约 12.21 MiB。图中的内存还计算了词输入、输出和导出的组合向量数组，因此高于这一数值。该指标是主要数组的静态合计，进程峰值内存还包括词表、缓存和运行开销。

### 6.4 查询语义与序列化

Gensim FastText 的成员查询可以表示“能够生成向量”。判断词是否真正存在于训练词表，应使用 `word in model.wv.key_to_index`。项目据此分别计算词表外比例和有效向量覆盖率。

### 6.5 框架论文与 Dictionary—TF-IDF—LSI 管线

`Dictionary.doc2bow()` 将分词文本转换成词项编号与次数，`filter_extremes()` 按文档频率筛选词表。本实验设置 `no_below=2`、`no_above=1.0`、`keep_n=40000`，词表从 1 月训练文章建立。`TfidfModel.initialize()` 扫描训练文档统计文档频率，`__getitem__()` 使用已拟合权重转换文档。

随后执行 `LsiModel(tfidf[train_bow], num_topics=64)`，再用同一模型转换验证和测试文章。若词项—文档矩阵记为 X，LSI 的低维投影可写为：

$$
X\approx U_k\Sigma_kV_k^\top,\qquad
\mathbf{z}_d=U_k^\top\mathbf{x}_d.
$$

`interfaces.TransformationABC._apply()` 包装转换语料，`TransformedCorpus.__iter__()` 在遍历时逐篇调用模型，体现论文的可组合接口。`LsiModel.add_documents()` 默认按块组织输入，`Projection` 调用 `stochastic_svd()` 计算块的分解，再合并投影。由此可以同时理解“统一接口”与“每个算法内部各自的数值实现”。函数行号与版本链接见源码索引。[7]

本项目为了向 scikit-learn 分类器提供矩阵，在最后一步把 64 维 LSI 向量汇集到内存。流式接口贯穿 Gensim 转换过程，整条作业管线的内存需求还包含分类特征和模型矩阵。

完整模型保存训练状态，适合继续训练；仅保存向量的方式适合查询，能力取决于保留下来的词和子词矩阵。FastText 在保存时可以排除随后重新计算的组合向量和缓存，载入后重建相应内容。项目对每个模型做了保存、重载和向量一致性检查，并手工重构已见词的组合向量以验证源码公式。

## 7. 文档向量与分类器

词向量可以通过平均聚合形成文档向量，也可以通过 IDF 强调更具区分力的词：

$$
\mathbf{d}=
\frac{\sum_{w\in d}a_w\mathbf{e}_w}{\sum_{w\in d}a_w}.
$$

平均方案的权重为 1，IDF 方案的权重由训练文档频率决定。Word2Vec 对可用词向量聚合，FastText 进一步使用子词合成的向量。零向量与词覆盖比例一起记录，方便检查数据和表示的有效性。

密集文档向量先用训练集的均值和标准差进行标准化，再由线性 SVM 分类。密集表示的样本数高于维度，求解器采用原始问题形式；高维稀疏 TF-IDF 采用对偶形式。TF-IDF 使用词 unigram 与 bigram，保留至多 60,000 个特征；Gensim LSI 从训练词项的 TF-IDF 表示学习 64 个潜在维度。不同表示的输入特征具有各自特点，结果用来比较实际方案。

主要指标为准确率与 Macro-F1。准确率反映整体正确比例，Macro-F1 先对每类计算 F1 再平均，使样本较少的版面也获得相同权重：

$$
F1_c=\frac{2P_cR_c}{P_c+R_c},\qquad
\mathrm{MacroF1}=\frac{1}{C}\sum_{c=1}^C F1_c.
$$

指标区间按测试日期整组重采样 1,000 次，保留新闻的日内相关结构。区间反映这六个测试日期内部的变化，对更长时间范围的判断需要更多日期和样本支持。

## 11. 监督 FastText 论文结构的补充实操

监督论文先把词与词 n-gram 特征映射到向量，再平均成文档表示，最后预测类别。其核心损失可以表示为：

$$
\mathbf{h}=\frac{1}{m}\sum_{i=1}^m\mathbf{a}_{x_i},\qquad
\mathcal{L}=-\log\mathrm{softmax}(B\mathbf{h})_y.
$$

项目用 `EmbeddingBag(mode="mean")` 实现平均特征表示，用无偏置线性层实现输出矩阵，并共同更新两层参数。词 bigram 使用稳定的 FNV-1a 哈希映射到 20,000 个额外桶，保留有限的局部词序信息。词序特征与主实验的字符子词具有不同的粒度。

训练采用 SGD 和线性学习率衰减，尝试 0.1、0.5、1.0 三种初始学习率，通过验证集选择学习率与 1—30 轮中的最佳检查点。小批次梯度按文档数量累加，以对应论文逐文档 SGD 的更新尺度。输入最多保留前 1,200 个词，使用按类别频次计算的交叉熵权重。这些是适合本数据规模的工程设置。

本任务只有 2—6 类，因此结构复现采用完整 softmax。原论文的层次 softmax 用于大类别空间，基于 Huffman 路径降低计算开销；它与 Gensim 的上下文层次目标共享树结构思路，但输出对象分别为类别与上下文词。

六类任务中，单词特征与双词增强的测试 Macro-F1 分别为 **0.4172** 和 **0.4344**，验证选择的学习率分别为 1 与 1，最佳轮次为 13 与 13。这些数值展示本次结构复现的效果。PyTorch 小批次实现、类别权重和输入长度等条件与原 C++ 实现各有设置，耗时仅反映本机补充实验。

## 12. 检查、复现与收获

数据检查确认训练、验证、测试文章 ID 和清洗内容哈希各自独立。语料清洗测试覆盖读音、全角字符、标点和文章边界；小模型集成测试覆盖可重复遍历、训练、保存、重载和词表外向量。所有正式词向量模型的保存重载最大误差均记录在结果 JSON 中，FastText 组合向量重构误差也单独记录。

完整复现命令：

```bash
export PYTHONHASHSEED=0
python scripts/run.py all --archive "/path/to/1998-上半年-带音.rar"
python scripts/audit_sources.py
python -m unittest discover -s tests -v
python scripts/verify_results.py
```

首次运行前按 README 配置 Python 3.11 环境。`audit_sources.py` 应先执行，以生成环境和源码映射；分阶段命令可以分别执行 prepare、embeddings、evaluate、paper、plot、report。现有词向量模型依据参数与语料哈希核对后复用，参数或语料变化会触发相应模型重新训练。

本次实验形成了几个具体认识。首先，表示学习与分类训练承担不同目标，论文、接口和实验需要逐一对应。其次，词表阈值、采样表、迭代器和序列化都是有效训练的一部分。再次，子词覆盖能力与下游分类能力需要分别评价；参数选择由验证结果和资源需求共同支持。最后，标签与划分定义了结论范围，真实版面分类提供可追溯的小实验，新闻主题泛化还需要专门标签与更丰富的评价材料。
